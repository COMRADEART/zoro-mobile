# Signing & building a release AAB

Two supported paths. **No keys, keystores, or service-account files are committed by this guide — and they must never be.** Run these on your machine.

Your `eas.json` already defines a `release` profile that builds an Android **app-bundle** (`.aab`), which is what Play requires.

---

## Path 1 — EAS Build (recommended)

Expo generates and securely stores the upload keystore for you; nothing secret touches the repo.

```bash
npm i -g eas-cli          # if not installed
eas login
eas build:configure       # links the project (one-time)

# Build a signed release app-bundle in the cloud:
eas build --platform android --profile release
# First run: choose "Generate new keystore" when prompted — EAS stores it.
```

Download the resulting `.aab` from the build page and upload it to a Play **testing track** first (Internal testing), not Production.

Inspect/back up the managed credentials any time:
```bash
eas credentials            # view / download the keystore EAS holds
```
Keep an offline backup of that keystore — losing it means you can't update the app under the same listing (unless enrolled in Play App Signing, which is the default and strongly recommended; enroll when prompted in Play Console).

### Submitting via EAS (optional)

`eas.json` → `submit.production.android.serviceAccountKeyPath` points to `./path-to-service-account.json` (a placeholder). To use `eas submit`:
1. Create a Google Play service account JSON in Play Console → Setup → API access.
2. Save it **outside the repo** (or at a gitignored path) and update the path in `eas.json` — **never commit the JSON.**

## Path 2 — Local keystore + Gradle (bare/prebuild)

Use this only if you build `android/` locally instead of EAS.

1. Generate an upload keystore (store it OUTSIDE the project, e.g. `~/keys/`):
   ```bash
   keytool -genkeypair -v -keystore ~/keys/santoryu-upload.jks \
     -alias santoryu-upload -keyalg RSA -keysize 2048 -validity 10000
   ```
   Record the passwords in a password manager. **This file is your identity for the app — back it up; do not lose it; do not commit it.**

2. Put credentials in `~/.gradle/gradle.properties` (user-global, outside the repo):
   ```properties
   SANTORYU_UPLOAD_STORE_FILE=/absolute/path/to/santoryu-upload.jks
   SANTORYU_UPLOAD_KEY_ALIAS=santoryu-upload
   SANTORYU_UPLOAD_STORE_PASSWORD=********
   SANTORYU_UPLOAD_KEY_PASSWORD=********
   ```

3. Wire the `release` signingConfig in `android/app/build.gradle` to read those properties. Note: `android/` is **gitignored and regenerated by `expo prebuild`**, so make this durable with a config plugin (mirror the pattern in `plugins/withAndroidBackup.js`) rather than hand-editing the generated file.

4. Build:
   ```bash
   npx expo prebuild -p android
   cd android && ./gradlew bundleRelease
   # output: android/app/build/outputs/bundle/release/app-release.aab
   ```

---

## Never commit these

Add to `.gitignore` (root `/android` is already ignored; these cover the rest):

```gitignore
*.jks
*.keystore
**/google-services.json
**/path-to-service-account.json
*service-account*.json
```

If a keystore or service-account JSON is ever committed, treat the key as compromised: in Play App Signing you can reset the **upload** key (contact Play support / use the upload key reset flow); rotate the service account immediately.

## Pre-upload reminders

- Bump `android.versionCode` in `app.json` before every upload (Play rejects duplicate version codes). Currently `1`.
- Upload to **Internal testing** first; run the **Pre-launch report** and fix any crash before promoting to Production.
- Enroll in **Play App Signing** (default) so a lost upload key is recoverable.
